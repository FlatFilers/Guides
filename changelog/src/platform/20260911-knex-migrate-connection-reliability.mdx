### September 11, 2026

## dataxp

**More reliable data operations under heavy load**

Migrating a workbook to newer storage could previously fail with a spurious connection error when its underlying storage was slow to start up. These migrations now wait for the target to be ready and complete successfully.

Streaming or exporting the records of a large sheet could previously stop before finishing. These operations now run to completion.

Record counts also stay accurate and consistent during bursts of activity. Counts could previously lag, briefly move backward, or get recomputed redundantly. They're now computed once and kept consistent, so the counts you see and the `sheet:counts-updated` events you receive are more dependable. When you request a sheet's counts before they've finished computing for the first time, the API now waits briefly and, if they still aren't ready, returns a retriable error (HTTP 503) asking you to retry shortly, rather than a success response with the counts missing. A count of zero also comes back as the real value it is, instead of being mistaken for a count that hasn't been computed yet, so an empty sheet no longer leaves you waiting on a value that never arrives. This holds for any consumer of record counts, including the `api.sheets.getRecordCounts` SDK call and the underlying `GET /sheets/:sheetId/counts` endpoint. These improvements apply automatically, with nothing for you to configure or do.
